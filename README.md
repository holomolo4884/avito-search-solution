# Решение задачи кандидатогенерации для Авито Услуг

## Описание подхода

### Архитектура решения
Решение представляет собой гибридную систему поиска кандидатов, сочетающую классический информационный поиск (TF-IDF) с эвристическими правилами на основе доменных признаков.

### Использованные данные и признаки

**Текстовые признаки:**
- `search_query` — текст поискового запроса
- `item_title_raw` — заголовок объявления (умножен на 3 для повышения веса)
- `item_description_raw` — описание объявления

**Структурные признаки (используются как бусты):**
- `search_category` / `item_category_id` — категория поиска и объявления
- `search_location_id` / `item_location_id` — локация поиска и объявления

**Почему выбраны именно эти признаки:**
1. Текстовые признаки — основа семантического соответствия
2. Категория — самый сильный сигнал релевантности на Авито (пользователь явно указывает, где ищет)
3. Локация — критична для услуг (пользователь ищет исполнителей рядом)

### Модели и алгоритмы

**Основной алгоритм: TF-IDF с символьными n-граммами**
- `TfidfVectorizer` из `scikit-learn`
- Параметры: `analyzer='char_wb'`, `ngram_range=(3, 4)`
- Почему символьные n-граммы: устойчивы к опечаткам, морфологии русского языка и частичным совпадениям ("автоподбор" vs "авто подбор")
- Умножение заголовка на 3: заставляет модель считать слова в заголовке в 3 раза важнее, чем в описании

**Алгоритм поиска:**
1. Векторизация всех объявлений через TF-IDF
2. Для каждого запроса вычисляется косинусное сходство со всеми объявлениями
3. Отбирается топ-1000 кандидатов по текстовому сходству
4. Применяются эвристические бусты:
   - +0.5 за совпадение категории
   - +0.3 за совпадение локации
5. Финальная сортировка и выбор топ-50

### Проверка качества

**Внутренняя валидация:**
- Код содержит функцию `validate_output()`, которая проверяет:
  - Формат `query_id` (ровно 16 символов)
  - Формат `item_id` (16 символов hex)
  - Отсутствие дубликатов
  - Существование всех `item_id` в корпусе
  - Количество строк совпадает с количеством запросов

**Оценка до отправки:**
- Использовался подход "вслепую", так как в задаче нет явного train/val split
- Качество оценивалось по метрике Recall@50 на платформе
- Базовый результат: ~0.04 (нейросеть без fine-tuning)
- Финальный результат: ожидается 0.3-0.6 (TF-IDF + эвристики)

### Анализ ошибок и улучшения

**Типы ошибок, выявленные при анализе:**
1. **Нейросетевые эмбеддинги (rubert-tiny2) показали низкий Recall (~0.04)**
   - Причина: модель не дообучена на данных Авито, плохо понимает специфичные связи
   - Решение: переход на классический TF-IDF, который лучше работает с точным совпадением ключевых слов

2. **Проблемы с памятью (OOM) при обработке длинных описаний**
   - Причина: BERT-модели создают квадратичную по длине матрицу внимания
   - Решение: ограничение `max_seq_length=128` и уменьшение `batch_size`

3. **Потеря релевантных объявлений из-за различий в формулировках**
   - Причина: точное совпадение слов важно для услуг
   - Решение: использование символьных n-грамм, устойчивых к морфологии и опечаткам

### Воспроизводимость

**Требования:**
```bash
pip install pandas numpy scikit-learn pyarrow
```

**Запуск:**
```bash
python main.py
```

**Входные файлы:**
- `benchmark_queries.parquet`
- `benchmark_items.parquet`

**Выходной файл:**
- `answer.csv` — формат строго соответствует требованиям ТЗ

### Используемые библиотеки
- `pandas` — работа с данными
- `numpy` — числовые операции
- `scikit-learn` — TF-IDF векторизация и косинусное сходство
- `pyarrow` — чтение Parquet файлов

Все библиотеки open-source, решение работает полностью локально без обращений к внешним API.
